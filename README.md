------------------------------------------------------------------------------

                             OPENAIR-CN-5G
 An implementation of the 5G Core network by the OpenAirInterface community.

------------------------------------------------------------------------------

OPENAIR-CN-5G is an implementation of the 3GPP specifications for the 5G Core Network.
At the moment, it contains the following network elements:

* Access and Mobility Management Function (**AMF**)
* Authentication Server Management Function (**AUSF**)
* Location Management Function (**LMF**)
* Network Exposure Function (**NEF**)
* Network Slicing Selection Function (**NSSF**)
* Network Repository Function (**NRF**)
* Network Data Analytics Function (**NWDAF**)
* Policy Control Function (**PCF**)
* Session Management Function (**SMF**)
* Unified Data Management (**UDM**)
* Unified Data Repository (**UDR**)
* Unstructured Data Storage Function (**UDSF**)
* User Plane Function (**UPF**)

Each element implementation has its own repository: this repository (`oai-cn5g-upf`) is meant for UPF.

## The UPF datapath

This UPF forwards user-plane traffic with **eBPF/XDP** programs attached directly to the
N3 and N6 interfaces, rather than in user space. Packets are classified and forwarded in
the kernel, and user space only programs the BPF maps in response to PFCP signalling on N4.

A user-space fallback (`simpleswitch`) is retained and selected when
`enable_bpf_datapath` is disabled.

```
        N3 (gNB, GTP-U)                                   N6 (Data Network)
              │                                                   │
      ┌───────▼────────┐                               ┌──────────▼─────────┐
      │ xdp_n3_entry   │  XDP hook                     │   xdp_n6_entry     │  XDP hook
      └───────┬────────┘                               └──────────┬─────────┘
              └──────────────────┬────────────────────────────────┘
                                 ▼
                   tail-call pipeline (prog_array)
          ┌──────────────────────────────────────────────┐
          │ slot 0  session_lookup_ip   (IP  PDU session)│
          │ slot 1  session_lookup_eth  (ETH PDU session)│
          │ slot 2  pdr_match           (TS 29.244 PDR)  │
          │ slot 3  far_apply           (forward/encap)  │
          │ slot 4  qer_apply           (QoS)            │
          │ slot 5  urr_apply           (usage report)   │
          │ slot 6  bar_apply           (buffering)      │
          │ slot 7  mar_apply           (ATSSS steering) │
          └──────────────────────────────────────────────┘

    QoS enforcement additionally uses a TC-BPF classifier (qer_tc) attached to an
    HTB qdisc for per-QFI MBR/GBR; ETH PDU broadcast uses eth_broadcast_tc.
```

12 XDP programs and 2 TC-BPF programs are compiled with clang and loaded through
libbpf skeletons generated by `bpftool`.

### Feature support

Flags live under `upf.support_features` in the configuration file. Status reflects
what is implemented in the eBPF datapath today.

| Flag                  | Feature                                     | Status          |
| --------------------- | ------------------------------------------- | --------------- |
| `enable_bpf_datapath` | eBPF/XDP datapath (else `simpleswitch`)      | Implemented     |
| `enable_qos`          | QER — per-QFI rate limiting via TC-BPF/HTB   | Implemented     |
| `enable_eth_pdu`      | Ethernet PDU sessions                        | Implemented     |
| `enable_fr`           | Framed Routing (RFC 2865 / TS 29.061)        | Implemented     |
| `enable_urr`          | URR — usage reporting                        | Implemented     |
| `enable_bar`          | BAR — downlink buffering                     | Implemented     |
| `enable_mar`          | MAR — ATSSS steering                         | Implemented     |
| `enable_snat`         | Source NAT                                   | Implemented     |

## Getting started

### Prerequisites

A Linux kernel with XDP support (5.x or newer), plus `clang`, `bpftool` and `libbpf`.
The build script installs everything else, including the out-of-tree dependencies
(libbpf, bpftool, yaml-cpp, folly) under `build/ext/`.

This repository uses git submodules — clone recursively:

```bash
git clone --recurse-submodules https://github.com/openairinterface/oai-cn5g-upf.git
cd oai-cn5g-upf
```

### Build

A `Makefile` at the repository root wraps the build scripts:

```bash
make setup           # [ONE-TIME] install system and build dependencies
make build           # cmake configure + full compile (Debug)
make build-release   # ... Release
make rebuild         # [FASTEST] incremental recompile, no cmake re-run
make help            # all targets
```

The binary is produced at `build/upf/build/upf`.

Working on the BPF programs only:

```bash
make build-xdp       # compile BPF programs and regenerate skeletons
make xdp             # wipe skeletons, then rebuild them
make clean-xdp       # remove skeletons and BPF objects (keeps the cmake cache)
make clean-build     # delete the whole build tree
```

`make setup` and the underlying `build/scripts/build_upf` install system packages,
so they need privileges. Run the compile steps as your normal user — building as
root leaves root-owned artifacts in the tree that later break `git` and incremental
builds.

### Container images

```bash
docker build --target oai-upf --tag oai-upf:develop \
             --file docker/Dockerfile.upf.ubuntu .
```

Dockerfiles are provided for Ubuntu (`Dockerfile.upf.ubuntu`), Rocky Linux 9 and
RHEL 9. The UPF needs `NET_ADMIN`/`SYS_ADMIN` and access to the BPF filesystem to
attach XDP programs, so it must be run privileged or with those capabilities granted.

### Configuration

A sample configuration is in [etc/config.yaml](etc/config.yaml). It carries the
N3/N4/N6 interface definitions, the DNN/slice lists, the NRF registration settings
and the `support_features` flags listed above.
